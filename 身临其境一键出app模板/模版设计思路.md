# 身临其境-推理小说模版 · 设计思路

## 定位

一份填空式产品 spec。填完占位符，CC 读这一个文件就能独立完成一个推理游戏。核心问题：
**如何将叙事驱动的推理小说变成交互驱动的推理游戏**

## 结构逻辑

14 个章节形成一条完整的决策链：

> 做什么游戏 → 给谁玩 → 为什么做 → 长什么样 → 有哪些功能 → 功能怎么串 → 界面放什么 → 数据怎么存 → 怎么操作 → 什么规则不能动 → 有哪些角色和场景 → 技术边界 → 怎么开始开发 → 怎么验收

每一节都回答一个不可跳过的问题：

- **产品概览**：案件类型、阶段数、核心谜题——锚定 CC 对整个任务的理解框架
- **目标人群**：推理水平和设备偏好——约束后续所有交互复杂度的标尺
- **产品目的**：核心价值和成功标准——CC 在长任务中容易跑偏，这是一句话的校准器
- **视觉风格规范**：全文最重的一节。14 种风格选项逼填写者做选择；配色用 60-30-10 量化；排版、间距、圆角给数值范围；视觉反馈逐操作列举；动效写死时长和缓动曲线；音效明确要求不可省略。不这样写，CC 会输出默认黑白灰无动效的页面
- **功能清单**：P0/P1 优先级划定边界，每个功能绑定 SKILL 路径，强制 CC 读原始数据而非编造
- **用户动线**：功能流转关系表说清数据怎么流动，防止做出孤立模块
- **信息结构**：每个界面上放什么、怎么交互。推理板的拖拽、上板下板、双击查看等细节不写死，CC 会做成简单列表
- **数据设计**：实体关系直接决定数据结构，不写则 CC 自行发明，可能导致线索和角色无法关联
- **交互设计**：具体操作方式——关键词输入、线索质疑、攻略分层解锁的详细规定
- **核心机制约束**：整个模版的"宪法"，不可商量的规则集中管理，散在各处 CC 会遗漏
- **角色与场景概览**：枚举值约束创作范围，防止偏离原著
- **技术约束**：单 HTML 文件、零依赖、离线可用
- **开发指引**：简单指引怎么开始
- **验收标准**：最后一道防线。功能/推理逻辑/数据/交互/视觉/响应式 6 个维度逐条 checkbox，前面漏掉的约束在这里兜底

## 设计原则

1. **约束代替指令**：不规定 CC 怎么做，规定什么不能违反
2. **枚举代替开放**：案件类型、视觉风格、角色定位、场景类型全部给枚举值，压缩自由发挥空间，保证效果。档案卡、角色信息、线索信息由大模型根据skills信息开放设计
3. **视觉强制量化**：配色有比例、间距有数值、动效有时长、每个操作有对应反馈，保证基础交互体验

## 可玩性保证

模版通过 5 个互锁的机制保证游戏的可玩性下限：

1. **谎言-质疑机制 → 推理有爽点**：至少 3 个角色说谎，至少 1 条推理路径必须经过质疑才能通关。玩家不是被动收集线索，而是主动用证据当面对质——这是推理游戏最核心的爽感来源
2. **线索分层 → 探索有意义**：公开线索进场景就能拿，隐藏线索需要搜查，且仅凭公开线索不能直接得出真相。探索行为本身有了回报
3. **智能推荐 → 不会卡死**：每次对话后推荐 2-3 个话题，且只要一直点推荐就能触发所有关键词。保证了下限——最差情况下玩家也能推进
4. **攻略系统 → 卡关有出路但有代价**：渐进式 3 层提示，每层扣分且不可撤回。给了安全网，但用安全网有成本——比没提示好（不会弃玩），也比免费提示好（不会破坏成就感）
5. **阶段解锁不依赖质疑 → 保底推进**：质疑是奖励而非门槛。漏掉质疑游戏仍然能往下走，只是得分会低。防止玩家被锁死在某个环节

**机制保下限，内容决定上限。**
